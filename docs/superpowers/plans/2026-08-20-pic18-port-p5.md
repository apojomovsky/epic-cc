# PIC18 Port P5 (Interrupts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PIC18 interrupt support: `__attribute__((interrupt(N)))` handlers placed at the PIC18F4550's high-priority vector (`0x0008`), with a save/restore prologue/epilogue and `RETFIE`, plus direct SFR load/store through literal pointers (`inttoptr`). Acceptance: `interrupt_pic18.c` and `interrupt_gate_pic18.c` (SFR addresses adapted to PIC18) compile through the real PIC18 pipeline and run correctly in the `Pic18` simulator with the interrupt fired mid-run. `interrupt_mul.c` joins the acceptance at P6 (it needs `mul`/`div` lowering, which is P6's job; the PIC14 fixture bundles both, docs/29 P3's fixture-split precedent applies).

**Architecture:** everything target-independent about interrupts already exists and is shared: `Func.isr` (`msp430_intrcc` in the .ll return position), `legalize::duplicate_isr_shared` (shared-function duplication `f` → `f_isr`), `legalize::split_isr_routines` (routine duplication for the ISR context), and `alloc`'s disjoint ISR frame region (ISR root base = max physical frame end over non-ISR roots). P5's work is the PIC18-specific emission and simulation half, mirroring how P3's `iselcore` sharing + PIC18 lowering split the pointer work. `isel-pic18` gains (1) literal-pointer load/store (`inttoptr (i16 k to ptr)` — PIC18 SFRs live at `0xF60-0xFFF` and the access-bank GPR at `0x000-0x05F`, both reachable with `a=0`, no `BSR`; isel-pic18's `operand()` already handles the SFR segment), and (2) ISR emission: `.org 0x0008` after the 2-word reset header, the save prologue, the ISR body, the restore epilogue + `RETFIE`. `Pic18` gains the PIC14-compatible interrupt model: `fire_interrupt`/`request_interrupt`/`interrupt_pending`, INTCON gating (bit 7 GIE, bit 4 INT0IE, bit 1 INT0IF — identical bit layout to PIC14's INTCON, so the gating code transfers), and `RETFIE` restoring GIE.

**Tech Stack:** Rust, Cargo workspace, docker dev image (rustc 1.97.1, clang 20.1.8, `gpasm` 1.5.2). `Pic18` simulator + `gpasm -p p18f4550` are the oracles.

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md) §4 P5 row, §5's "Interrupt priority" open question, §1 (`interrupt_vectors` row: two vectors with priority levels, `[0x0008, 0x0018]`). PIC14 reference: [`docs/26-phase4-interrupts-plan.md`](../../26-phase4-interrupts-plan.md) (the full model, already implemented) and the existing `crates/sim` PIC14 interrupt code. Datasheet facts to `[VERIFY]` before hard-coding: vector addresses `0x0008` (high) / `0x0018` (low), INTCON `0xFF2` with GIE/GIEH bit 7, `INT0IE` bit 4, `INT0IF` bit 1, IPEN = RCON bit 7, PORTB `0xF81`, STATUS `0xFD8`, BSR `0xFE0`, FSR0L/H `0xFE9/0xFEA` (confirmed against gputils 1.5.2's `p18f4550.inc` and the PIC18F4550 data sheet).

## Ruling: single-vector compat mode (IPEN=0) in v1, no priority argument

docs/29 §5 flags "whether the `__interrupt` attribute grows a priority argument" as **not settled** and P5's first design question. This plan settles it:

**v1 targets the PIC18F4550's compatibility mode: one interrupt vector at `0x0008` (GIE = INTCON bit 7), the same gating model PIC14's `interrupt.c`/`interrupt_gate.c` use.** The reasons:

- clang's `-target msp430` proxy does not carry the interrupt number: `__attribute__((interrupt(N)))` appears only as the dropped attribute string `"interrupt"="N"`; the IR keeps the bare `msp430_intrcc` token. Two priority levels would need a number no stage currently parses (irparse change + IR change + device change + two save areas + IPEN config). None of the three acceptance fixtures needs two handlers.
- The PIC18F4550 with IPEN=0 runs exactly the single-vector GIE-gated mode PIC14's accepted fixtures exercise; the INTCON bit layout is identical, so the sim gating transfers byte-for-byte.
- docs/29's phase table lists `interrupt.c`, `interrupt_gate.c`, `interrupt_mul.c` as P5 acceptance; `interrupt_mul` actually needs `*`/`/` (P6), so P5's real acceptance is the single-handler pair anyway.

**Consequence:** a module with more than one `Func.isr` panics loudly in `isel-pic18` ("multiple ISRs not yet supported, single-vector compat mode"). Two-vector priority mode stays a documented follow-up (the device's `interrupt_vectors` already carries `[0x0008, 0x0018]` for when it lands).

**Cost if wrong:** a user with a two-handler program hits the loud panic instead of a compile. Recoverable: add the priority plumbing when a fixture needs it.

## Global Constraints

- **`isel` (PIC14) never regresses.** No changes to `crates/isel`, `crates/banking`, `crates/peephole` in this plan. The PIC14 interrupt fixtures keep passing unchanged.
- **`legalize`, `alloc`, `ir`, `irparse` are untouched.** The ISR marker, duplication, and disjoint region already work for both backends (verified: `legalize::duplicate_isr_shared` and `alloc`'s ISR base are device-agnostic; `alloc`'s ISR base code has no PIC14-specific bank assumption).
- **The save area lives in the common-RAM reservation.** `device::PIC18F4550.common_ram` extends to `(0x0000, 0x0009)` (was `(0x0000, 0x0003)`): bytes 0x0000-0x0003 stay `retval_lo`, bytes 0x0004-0x0008 become the fixed ISR save area (W, STATUS, BSR, FSR0L, FSR0H), reachable via the access bit (`a=0`) with no `BSR` dependency, exactly the PIC14 rationale for common RAM. `ram_banks` starts at `0x000A` so no global/local can overlap the reservation. The P2 e2e tests seed by address NAME from the map, so the shifted start is invisible to them.
- **The prologue saves W last-in-first-out, W restored last** (the PIC14 convention): the final `MOVF save,W` re-loads W and sets Z/N from it, so the interrupted code's flag state at the boundary is NOT preserved. This is the accepted PIC convention (the PIC14 backend has the same property, documented in docs/26's correctness-risks note); the fixtures do not depend on flag preservation across the interrupt.
- **ISR emission order:** header (`org 0x0000; goto __start`), then `.org 0x0008`, the ISR, then the ordinary functions, then `__start` (which may sit anywhere: PIC18 `GOTO`/`CALL` are absolute 20-bit, no paging). Non-ISR programs emit byte-identical asm (the ISR path is gated on `Func.isr`).
- **Literal SFR access needs no FSR/BSR:** a `load`/`store` through `inttoptr (i16 <k> to ptr)` targets a physical 12-bit address; `0x000-0x05F` is access-bank GPR, `0xF60-0xFFF` is the SFR segment, both reached with `a=0` and no `BSR`. `isel-pic18`'s `operand()` already emits `a=0` for both (the P3 Task-2 fix), so the literal arm routes through it for `MOVF`/`MOVWF`, and `MOVFF` for the memory-to-memory copy. A literal pointer beyond 12 bits (out of data space) panics loudly.
- Conventional commits, single line, ≤ 3 lines (project convention).

### Task 1: `device` — widen the PIC18F4550 common reservation

**Files:**
- Modify: `crates/device/src/lib.rs`
- Modify: `crates/device/tests/device.rs`

**Interfaces:**
- Produces: `device::PIC18F4550.common_ram == Some((0x0000, 0x000F))`, `PIC18F4550.ram_banks == &[(0x0010, 0x07FF)]`; `gpr_start() == 0x0010`. The fixed regions (retval 0x0000-0x0003, ISR save 0x0004-0x000F) are never overlapped by globals/locals.

**Design note (Task 1+3, refined): the save area is 12 bytes, not 5.** The ISR body can clobber more shared state than the PIC14 register set. PIC18-specific: (1) `TBLPTRU/H/L` are a 3-byte SFR triplet with no single load/store: a const read is a multi-instruction setup (`MOVLW LOW/HIGH/UPPER` + `MOVWF` x3 + carries), and an interrupt taken mid-setup leaves a torn `TBLPTR`; the ISR body's own const reads would then see the preempted main's half-set pointer. (2) `retval_lo` (0x0000-0x0003) is live across the callee's `RETURN`→caller-copy window: an ISR that itself calls a value-returning function would clobber the preempted main's in-flight return value (the exact hazard PIC14's M13 epilogue documents and solves by snapshotting the retval region into its save area). So the save area is:
  - `0x0004` W (saved last in the prologue, `MOVWF` clobbers nothing)
  - `0x0005` STATUS (`0xFD8`), `0x0006` BSR (`0xFE0`), `0x0007` FSR0L (`0xFE9`), `0x0008` FSR0H (`0xFEA`), `0x0009` TBLPTRL (`0xFF6`), `0x000A` TBLPTRH (`0xFF7`), `0x000B` TBLPTRU (`0xFF8`)
  - `0x000C-0x000F` the retval snapshot (4 bytes: the preempted main's in-flight return value, copied to/from `retval_lo`)
  PIC18's `MOVFF` never touches STATUS, so the EPILOGUE can restore STATUS and then W *via MOVFF* (no nibble-swap dance) and still preserve the interrupted Z/N: `MOVFF save,STATUS` restores STATUS (whose Z/N reflect the interrupted main), then `MOVFF save,W` reloads W with no flag side effect. This is strictly better than PIC14's swap-back (which clobbers the restored flags with the moved W's Z/N); the fixtures do not depend on it, but the design takes it.

### Task 3: `isel-pic18` — ISR vector entry, prologue, epilogue

**Files:**
- Modify: `crates/isel-pic18/src/lib.rs` (`select`, `emit_inst` Ret arm)
- Modify: `crates/isel-pic18/tests/isel_pic18.rs`

**Interfaces:**
- Consumes: `Func.isr` (already parsed), `device::PIC18F4550` (vector `0x0008`; the save area at `0x0004-0x000F` from Task 1).
- Produces: `ISR_SAVE_LO = 0x0004` (12 bytes: W, STATUS, BSR, FSR0L, FSR0H, TBLPTRL, TBLPTRH, TBLPTRU + 4-byte retval snapshot); `select` emits:
  - Header: `org 0x0000` + `goto __start` (unchanged), then if the module has an ISR: `org 0x0008` + the ISR body, then the rest.
  - ISR prologue:
    ```
    MOVFF 0x0000, 0x000C   ; retval snapshot (4 bytes: 0x0000-3 -> 0x000C-F)
    MOVFF 0x0001, 0x000D
    MOVFF 0x0002, 0x000E
    MOVFF 0x0003, 0x000F
    MOVFF 0xFD8, 0x0005    ; STATUS
    MOVFF 0xFE0, 0x0006    ; BSR
    MOVFF 0xFE9, 0x0007    ; FSR0L
    MOVFF 0xFEA, 0x0008    ; FSR0H
    MOVFF 0xFF6, 0x0009    ; TBLPTRL
    MOVFF 0xFF7, 0x000A    ; TBLPTRH
    MOVFF 0xFF8, 0x000B    ; TBLPTRU
    MOVWF 0x0004,A         ; W last (MOVWF clobbers nothing)
    ```
    (All MOVFF saves first — none touch STATUS — then W, whose `MOVWF` also never touches STATUS. The retval snapshot first, matching PIC14 M13's ordering rationale: the ISR body's value-returning calls would otherwise clobber the preempted main's in-flight return value.)
  - ISR epilogue (replacing `ret void`), MOVFF-based so the interrupted Z/N survive (MOVFF never sets flags), W restored LAST:
    ```
    MOVFF 0x000F, 0x0003    ; restore retval snapshot
    MOVFF 0x000E, 0x0002
    MOVFF 0x000D, 0x0001
    MOVFF 0x000C, 0x0000
    MOVFF 0x000B, 0xFF8     ; restore TBLPTRU
    MOVFF 0x000A, 0xFF7     ; restore TBLPTRH
    MOVFF 0x0009, 0xFF6     ; restore TBLPTRL
    MOVFF 0x0008, 0xFEA     ; restore FSR0H
    MOVFF 0x0007, 0xFE9     ; restore FSR0L
    MOVFF 0x0006, 0xFE0     ; restore BSR
    MOVFF 0x0005, 0xFD8     ; restore STATUS (flags come back, incl. Z/N)
    MOVF  0x0004, W, A      ; restore W (sets Z/N from the moved value)
    RETFIE
    ```
  **W cannot be restored by MOVFF (W is not a file register).** The W restore is `MOVF 0x0004, W, A`, which sets Z/N from the restored W — the accepted PIC convention, matching PIC14's documented W-last flag limitation. The STATUS restore via MOVFF comes first, so the interrupted main's flags survive until the W restore's own Z/N clobber (the one flag loss both backends accept).
  - The ISR body between prologue and epilogue is ordinary block emission (BSR tracking resets at the ISR label via `emit_label`, exactly as it does for any function).
  - A module with > 1 `Func.isr` panics loudly ("multiple ISRs not yet supported (single-vector compatibility mode)").
  - An ISR that returns a value (`Func.ret.is_some()` on the ISR) panics ("interrupt handler must return void").
  - `Inst::Ret(None)` in a non-ISR function still emits plain `RETURN`; in an ISR it emits the epilogue + `RETFIE`.

### Task 4: `sim` — the PIC18 interrupt model

**Files:**
- Modify: `crates/sim/src/lib.rs`
- Modify: `crates/sim/tests/pic18.rs` (integration tests) or the in-crate `#[cfg(test)] mod`

**Interfaces:**
- Produces (all on `Pic18`):
  - `fire_interrupt()` — push `pc` (the next-unexecuted instruction; called between steps) and set `pc = 0x0008`, clearing GIE (INTCON bit 7) on entry.
  - `request_interrupt()` — latch a pending interrupt (sets INTCON bit 1, INTF; `pending = true`), taken at the next step boundary when INTCON bits 7 (GIE) and 4 (INT0IE) are both set (the PIC14 gating transfer; PIC18 INTCON has the same bit layout).
  - `interrupt_pending() -> bool`.
