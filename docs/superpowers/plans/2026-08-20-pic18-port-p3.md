# PIC18 Port P3 (Pointers, Arrays, Structs) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `isel-pic18` gains pointer support (`getelementptr` folding, `load`/`store` through a runtime RAM pointer, `alloca`, constant-length `memcpy`, and `byval`/`sret` struct calling convention), bringing PIC18 codegen to the same C surface PIC14's own milestone 5 covered. Acceptance: `array.c`, `banked_ptr.c`, `structs.c`, and a new PIC18-specific `ptr_probe.c` (see the fixture-scope note below) compile through the real driver pipeline and run correctly in the `Pic18` simulator.

**Architecture:** the GEP-chain-folding algorithm PIC14's `isel` already has (`Base`, the `resolved` map, the fixpoint scan over `Inst::Gep`) is pure IR analysis with zero PIC14-specific addressing in it, so it moves into `iselcore` as a shared pass rather than being duplicated: the first real payoff of the crate split docs/29 anticipated. `isel-pic18`'s own new work is the *lowering* half: a resolved pointer with no dynamic terms is a plain direct address (no FSR at all); one with a dynamic term needs `LFSR` to seed the base into an `FSRn` pair and `INDFn` to access through it, with **no PIC14-style bank/window bookkeeping at all**, since a PIC18 `FSRn` is a flat 12-bit register spanning the entire data space. The `fsr_window`/`object_span`-for-window-checks machinery PIC14 needs simply has no PIC18 analog and is not ported.

**Tech Stack:** Rust, Cargo workspace, `nix develop` dev shell. `gpasm -p p18f4550` (byte-for-byte) and the `Pic18` simulator are the acceptance oracles, exactly as in P1/P2.

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md), §4's P3 row, §2 D-1 (parallel backend crates: this plan's Task 1 is the first thing to actually move code into the shared `iselcore` crate D-1 created), §2 D-2 (`Slot`, already landed in P0/P2, untouched here since P3 never constructs anything but `Slot::Direct`). The proven PIC14 reference is [`docs/18-phase3-pointers-const-plan.md`](../../18-phase3-pointers-const-plan.md) and its implementation, `crates/isel/src/lib.rs` (the `Base`/`Addr`/`resolved_for`/`emit_ptr_*`/`object_span` functions, and the GEP fixpoint-fold block starting around line 5537).

## Scope boundary

**In scope:** `Inst::Gep` (folding, both `GepBase::Global` and `GepBase::Reg` chains), `Inst::Alloca` (a virtual slot seed, no codegen of its own), `Inst::Load`/`Inst::Store` through a `%reg` pointer operand (not just `@global`, which P2 already handles), `Inst::Memcpy` with `MemLen::Const` only, and `byval`/`sret` call arguments whose value is a resolved pointer (extending what P2's `Inst::Call` arm already does for the "always a plain slot" case).

**A pointer GEP with more than one dynamic term is out of scope and panics loudly.** None of this plan's four acceptance fixtures need it (verified against every fixture below); PIC14's own `isel` needed the general N-term case eventually, but added it later, not as part of its own milestone 5. If a later fixture needs it, extending the single-term path (Task 6) to loop over `terms` the way PIC14's `emit_accum_terms` does is mechanical, but speculatively building it now, untested, is exactly the kind of code this codebase's `ROUTINE_NAMES`-panic convention exists to avoid.

**Out of scope**, matching docs/29's phase table exactly: `const` (flash) globals and `TBLRD` (P4, see the fixture-scope note immediately below), interrupts (P5), 32-bit `long` (P6), soft-float (P7), and **dynamic-length `memcpy`** (`MemLen::Reg`, PIC14 issue #4, landed on PIC14 as a later, separate issue, not part of its own milestone 5; none of this plan's fixtures need it either).

## Fixture-scope note: `ptr_probe.c` splits across P3 and P4

PIC14's own `ptr_probe.c` fixture (`crates/driver/tests/fixtures/ptr_probe.c`) is:

```c
volatile unsigned short in;
volatile unsigned char out;
static const unsigned char table[4] = {10, 20, 30, 40};
volatile unsigned char ram[8];
void main(void) {
    unsigned char i = (unsigned char)(in & 3);
    volatile unsigned char *p = ram + i;
    *p = table[i];
    out = *p;
}
```

PIC14's own phase 3 plan (`docs/18-phase3-pointers-const-plan.md`) bundled the RAM pointer (`ram + i`) *and* the const-flash table read (`table[i]`) into one milestone, because on PIC14 a `const` read is cheap (`RETLW` table, already needed for other reasons) and the spike's original probe exercised both together. docs/29 deliberately does **not** make the same bundling choice for PIC18: `TBLRD` is its own, materially larger, P4 phase. So this plan's fixture is a new `ptr_probe_pic18.c`, the same RAM-pointer shape with the `const` table and the `table[i]` read removed, and the *exact* `ptr_probe.c` (RAM pointer feeding a const-flash read) becomes a P4 acceptance addition once `TBLRD` exists, at which point running the untouched original fixture through both backends becomes a clean parity check. This plan's Task 11 creates the substitute fixture; nothing here touches the original file.

`array.c`, `banked_ptr.c`, and `structs.c` have no `const` globals (verified: `grep -n const` on each finds nothing but comments), so they need no substitution.

## Global Constraints

- **`isel` (PIC14) must never regress.** Task 1 moves code out of it into `iselcore`; that move must be pure and behavior-preserving, meaning `cargo test -p isel` shows the exact same test count and every existing assertion text unchanged, before and after.
- **`alloc`, `device`, `banking`, `peephole`, `driver`, `legalize`, `callgraph`, `ir`, `irparse`, `wholeprog` are not touched.** `alloc` already handles `Inst::Alloca` sizing and `is_const` global exclusion generically (verified: `crates/alloc/src/lib.rs:520` matches `Inst::Alloca` with no device-specific branch); `driver` already dispatches `isel_pic18::select` for `Core::Pic18` (`crates/driver/src/main.rs:75`, from P2's Task 14). Nothing in this plan needs either to change.
- **No `PLUSWn` for dynamic-offset writes.** `PLUSWn` computes its effective address from `FSRn + W` at the instant the instruction executes; a *write* needs `W` to simultaneously hold the byte being stored, which collides with using `W` as the offset. Every dynamic pointer access in this plan physically advances `FSRnL`/`FSRnH` (`LFSR` for the static base, `ADDWF`/`ADDWFC` for the dynamic term) and then accesses through plain `INDFn`, for both reads and writes, never `PLUSWn`. This applies uniformly so a later "optimization" doesn't introduce the write hazard by special-casing reads.
- **No FSR-window checks.** PIC14's `fsr_window`/the window half of `object_span` exist only because PIC14's four RAM banks are non-contiguous; PIC18's `FSRn` is a flat 12-bit register over the whole data space, so no object can ever straddle a boundary that matters. This machinery is not ported. Its absence is a deliberate simplification, not an oversight, and Task 5's doc comment says so.
- Conventional commits, single line, at most 3 lines. Branch: `feat/pic18-p3-pointers`, created fresh from `master` (P0/P1/P2 already merged).

```rust
use ir::{GepBase, Inst, Module};

/// Where a pointer's bytes ultimately live, once every `gep` in its chain
/// has been folded away: a named global, or a local slot (an alloca's own
/// buffer, or a byval/sret param, where the `bool` is `true` for sret, meaning
/// the slot holds a target ADDRESS rather than being the object itself).
#[derive(Clone, Debug)]
pub enum Base {
    Global(String),
    Slot(String, bool),
}

/// Fold every `Inst::Gep` in `m` to `(base, k, terms)`: `base` is where the
/// chain ultimately starts, `k` is the constant byte offset, `terms` is
/// `Vec<(scale, reg)>` for every dynamic (register-indexed) offset in the
/// chain, inner-to-outer. Keyed `{func}::{reg}` via `ssa_key`, matching
/// every other per-function map in this pipeline.
///
/// Seeds first (byval/sret params, allocas, each its own `Base::Slot`
/// with no offset), then a fixpoint scan over every `Gep`: a `GepBase::Reg`
/// folds in its own already-resolved entry (`k` adds, `terms` concatenate
/// inner-first) until the chain bottoms out at a `Global` or a seed. A
/// `Gep` whose base is neither a seed nor another (eventually resolvable)
/// `Gep` is a bug in an earlier stage and panics loudly; a scan that makes
/// no progress with unresolved geps left is a cycle and panics loudly.
pub fn resolve_pointers(m: &Module) -> HashMap<String, (Base, u8, Vec<(u8, String)>)> {
    let mut geps: HashMap<String, ir::Gep> = HashMap::new();
    let mut resolved: HashMap<String, (Base, u8, Vec<(u8, String)>)> = HashMap::new();
    for f in &m.funcs {
        for p in &f.params {
            if p.byval.is_some() {
                resolved.insert(ssa_key(&f.name, &p.name), (Base::Slot(p.name.clone(), false), 0, Vec::new()));
            } else if p.sret {
                resolved.insert(ssa_key(&f.name, &p.name), (Base::Slot(p.name.clone(), true), 0, Vec::new()));
            }
        }
        for b in &f.blocks {
            for i in &b.insts {
                match i {
                    Inst::Gep(g) => {
                        geps.insert(ssa_key(&f.name, &g.dst), g.clone());
                    }
                    Inst::Alloca(a) => {
                        resolved.insert(ssa_key(&f.name, &a.dst), (Base::Slot(a.dst.clone(), false), 0, Vec::new()));
                    }
                    _ => {}
                }
            }
        }
    }
    for f in &m.funcs {
        let fname = f.name.clone();
        let mut pending: Vec<(String, ir::Gep)> = geps
            .iter()
            .filter(|(k, _)| k.starts_with(&format!("{fname}::")))
            .map(|(k, g)| (k.clone(), g.clone()))
            .collect();
        let mut progressed = true;
        while progressed {
            progressed = false;
            let mut rest = Vec::new();
            for (key, g) in pending {
                match &g.base {
                    GepBase::Global(name) => {
                        assert!(!resolved.contains_key(&key), "iselcore: duplicate definition of pointer reg {key}");
                        resolved.insert(key, (Base::Global(name.clone()), g.k, g.terms.clone()));
                        progressed = true;
                    }
                    GepBase::Reg(r) => {
                        let rkey = ssa_key(&fname, r);
                        if let Some((b, kk, tt)) = resolved.get(&rkey).cloned() {
                            assert!(!resolved.contains_key(&key), "iselcore: duplicate definition of pointer reg {key}");
                            let mut terms = tt.clone();
                            terms.extend(g.terms.clone());
                            let k = g.k.checked_add(kk).unwrap_or_else(|| panic!("iselcore: gep offset overflow in {key}"));
                            resolved.insert(key, (b, k, terms));
                            progressed = true;
                        } else if geps.contains_key(&rkey) {
                            rest.push((key, g));
                        } else {
                            panic!("iselcore: no gep for pointer %{r} (chain base missing, key {rkey})");
                        }
                    }
                }
            }
            pending = rest;
            if !progressed && !pending.is_empty() {
                let names: Vec<&str> = pending.iter().map(|(k, _)| k.as_str()).collect();
                panic!("iselcore: cyclic gep chain involving {names:?}");
            }
        }
    }
    resolved
}
```

**Why this is its own task, before any FSR code exists.** PIC18's Access Bank is two disjoint ranges: the low general-purpose segment (`0x000-0x05F`) *and* the high SFR segment (`0xF60-0xFFF`, where `FSR0L`/`FSR0H`/`FSR1L`/`FSR1H`/`FSR2L`/`FSR2H` and every other SFR live), both reachable with the access bit `a=0` and **no** `MOVLB`, regardless of the current `BSR`. `operand()` as it stands treats every address `>= 0x60` as needing a `MOVLB`, which is correct for the banked GPR middle range (`0x060-0xF5F`) but wrong for the SFR range: calling `operand(0xFE9)` (FSR0L) today would emit a spurious `MOVLB 0xF` and address it as `,B`, architecturally wrong, since FSR0L must always be accessed as `,A`. `[VERIFY]` the exact SFR-segment floor against DS39632 before trusting `0xF60` as anything but a placeholder to search-and-replace once confirmed; the four FSR pairs' own literal addresses (`0xFE9`/`0xFEA`, `0xFE1`/`0xFE2`, `0xFD9`/`0xFDA` for FSR0/1/2 respectively) are already load-bearing elsewhere in this codebase (`crates/sim/src/lib.rs:1004-1006`) and are not themselves in question; only the general floor this task adds is new.

Because `operand()` is a private method on `Gen`, this task's test is a `#[cfg(test)] mod` appended directly inside `crates/isel-pic18/src/lib.rs`, not a separate integration-test file.     /// The `,A`/`,B` operand components `(a, f)` for a physical address
```rust
    /// used by a `W`-routing instruction (`ADDWF`/`SUBWF`/.../`CPFSxx`/
    /// `MOVWF`), emitting `MOVLB` first if the tracked `BSR` doesn't
    /// already match. PIC18's Access Bank is TWO disjoint ranges: the low
    /// general-purpose segment (`0x000-0x05F`) and the high SFR segment
    /// (`0xF60-0xFFF` [VERIFY against DS39632], every SFR, including
    /// FSR0L/FSR0H/FSR1L/FSR1H/FSR2L/FSR2H, lives here), BOTH always
    /// reachable via `a=0` with no `MOVLB`, regardless of `BSR`. Only the
    /// MIDDLE range (`0x060-0xF5F`, ordinary banked GPR) needs a bank
    /// select. Getting this wrong for the SFR segment would emit a
    /// `MOVLB` before every FSR-setup write and address FSRnL/FSRnH as
    /// `,B`, architecturally wrong; hardware requires `,A` for the SFR
    /// segment unconditionally.
    ///
    /// `MOVFF`-based plain copies (`emit_copy_byte`, above) never call
    /// this: they take full 12-bit addresses directly and need no bank
    /// bit at all, which is why `Load`/`Store`/`Phi`-copies/`Call`-arg-
    /// copies never touch `BSR`.
    fn operand(&mut self, addr: u16) -> (u16, u16) {
        if addr < 0x60 || addr >= 0xF60 {
            (0, addr & 0xFF)
        } else {
            let bank = (addr >> 8) as u8;
            if self.bsr != Some(bank) {
                self.emit(format!("    MOVLB 0x{bank:X}"));
                self.bsr = Some(bank);
            }
            (1, addr & 0xFF)
        }
    }
```

```rust
    /// How a byte access at `ptr + byte_off` completes. `Val::Global`
    /// resolves directly (globals are never behind another indirection
    /// layer). `Val::Reg` looks up the pointer's fold via `resolved_for`:
    /// a `Base::Global`/`Base::Slot(_, false)` (byval/alloca, the slot
    /// itself IS the object) with no dynamic terms is a plain direct
    /// address; with dynamic terms it needs FSR0 (Task 6). A
    /// `Base::Slot(_, true)` (sret, the slot holds a target ADDRESS, not
    /// the object) always needs FSR0, regardless of terms (Task 7).
    fn emit_ptr_setup(&mut self, ptr: &Val, byte_off: u8) -> Addr {
        match ptr {
            Val::Global(g) => Addr::Direct(self.global_addr(g) + u16::from(byte_off)),
            Val::Reg(r) => {
                let (base, k, terms) = self.resolved_for(r);
                match &base {
                    Base::Global(name) => {
                        if terms.is_empty() {
                            Addr::Direct(self.global_addr(name) + u16::from(k) + u16::from(byte_off))
                        } else {
                            self.emit_fsr0_dynamic(self.global_addr(name), k, &terms, byte_off);
                            Addr::Indirect
                        }
                    }
                    Base::Slot(sname, indirect) => {
                        let sa = self.slot_addr(self.cur_func, sname).direct();
                        if !indirect && terms.is_empty() {
                            Addr::Direct(sa + u16::from(k) + u16::from(byte_off))
                        } else if !indirect {
                            self.emit_fsr0_dynamic(sa, k, &terms, byte_off);
                            Addr::Indirect
                        } else {
                            self.emit_fsr0_indirect_slot(sa, k, &terms, byte_off);
                            Addr::Indirect
                        }
                    }
                }
            }
            Val::Const(_) => panic!("isel-pic18: pointer operand must be a register or global"),
        }
    }
```

```rust
    /// register/global source via `MOVF`. Used only by the
    /// `Addr::Indirect` store path (the direct path uses
    /// `emit_move_val_to_slot`/`MOVFF`, which never touches `W`).
    fn emit_byte_to_w(&mut self, val: &Val, k: u8) {

                let (ab, f) = self.operand(a);
                self.emit(format!("    MOVF 0x{f:03X},W,{}", if ab == 0 { "A" } else { "B" }));
```

```rust
    /// The byte size of the object a resolved pointer's base ultimately
    /// refers to: a global's declared size, or a slot's (an alloca's
    /// buffer size, or a byval/sret param's declared width). Used to size
    /// a struct-copy loop (byval call args, sret returns; Tasks 7-8).
    ///
    /// Unlike PIC14's `object_span`, this has NO window-fit check baked
    /// in: PIC18's flat FSR addressing has no window an object could
    /// straddle (see this plan's Global Constraints). This function only
    /// ever answers "how many bytes," never "does it fit."
    fn object_span(&self, base: &Base) -> u16 {
        match base {
            Base::Global(name) => self
                .m
                .globals
                .iter()
                .find(|g| g.name == *name)
                .unwrap_or_else(|| panic!("isel-pic18: unknown global @{name}"))
                .size as u16,
            Base::Slot(sname, _) => {
                let f = self
                    .m
                    .funcs
                    .iter()
                    .find(|f| f.name == self.cur_func)
                    .unwrap_or_else(|| panic!("isel-pic18: no span for slot {sname}: unknown function {}", self.cur_func));
                if let Some(p) = f.params.iter().find(|p| p.name == *sname) {
                    p.width as u16
                } else if let Some(a) = f.blocks.iter().flat_map(|b| &b.insts).find_map(|i| match i {
                    Inst::Alloca(a) if a.dst == *sname => Some(a.size),
                    _ => None,
                }) {
                    a as u16
                } else {
                    panic!("isel-pic18: no span for slot {sname} in {}", self.cur_func)
                }
            }
        }
    }
```

### Task 6: Dynamic (single-term) pointer offsets via `FSR0`

**Files:**
- Modify: `crates/isel-pic18/src/lib.rs` (replace the Task 4 stub `emit_fsr0_dynamic`)
- Modify: `crates/isel-pic18/tests/isel_pic18.rs`

**Interfaces:**
- Consumes: `Gen::operand` (fixed in Task 2), `iselcore::Base`.
- Produces: a real `Gen::emit_fsr0_dynamic(&mut self, base_addr: u16, k: u8, terms: &[(u8, String)], byte_off: u8)`, called from `emit_ptr_setup`'s `Addr::Indirect` arms.

**Design note: why byte-by-byte re-setup, not FSR auto-increment.** A multi-byte load/store (an `i16`, or a multi-byte struct-array element) could in principle set `FSR0` once and walk it with `POSTINC0` across all the bytes. This plan does NOT do that: `emit_ptr_setup` is called once **per byte** (see Task 4), independently recomputing `FSR0 = base + k + terms + byte_off` from scratch every time. This is slightly more instructions per multi-byte access, but it keeps the FSR-setup logic a pure function of `(base, k, terms, byte_off)` with no hidden state ordering dependency between calls, the exact kind of implicit sequencing assumption that this codebase's own comments (see `crates/isel-pic18/src/lib.rs`'s extensive notes on `BSR` tracking and label resets) flag as a repeated source of miscompiles elsewhere in this project. Revisit only if profiling ever shows this matters; nothing in P3's scope needs the saved instructions.

**Scope: single term only.** `terms.len() > 1` panics loudly (see this plan's Scope boundary section). `terms.len() == 1`'s scale factor (`1` for a byte array, `2`/`4` for i16/i32/struct-element arrays) is handled by unrolling `scale` additions, mirroring PIC14's `emit_accum_terms` exactly.

```rust
    /// Set `FSR0 = base_addr + k + Σ scale×%reg + byte_off` and leave the
    /// access to go through `INDF0` (0xFEF). `LFSR` seeds the STATIC part
    /// (`base_addr + k + byte_off`, all known at codegen time: one
    /// two-word instruction, no addressing-mode complexity at all); the
    /// dynamic term, if any, is then added onto `FSR0L`/`FSR0H` with
    /// carry via `ADDWF`/`ADDWFC` (both routed through `operand()`, which
    /// Task 2 taught to recognize FSR0L/FSR0H as the always-access-bank
    /// SFR segment, so no `MOVLB` is ever emitted for these two writes).
    ///
    /// `terms.len() > 1` is out of scope for P3 (see this plan's Scope
    /// boundary) and panics loudly rather than silently dropping a term.
    fn emit_fsr0_dynamic(&mut self, base_addr: u16, k: u8, terms: &[(u8, String)], byte_off: u8) {
        assert!(
            terms.len() <= 1,
            "isel-pic18: multi-term dynamic pointer offsets not yet supported (P3 scope; {} terms)",
            terms.len()
        );
        let static_part = u16::from(k) + u16::from(byte_off);
        let lit = (base_addr + static_part) & 0xFFF;
        self.emit(format!("    LFSR 0, 0x{lit:03X}"));
        if let Some((scale, reg)) = terms.first() {
            let a = self.slot_addr(self.cur_func, reg).direct();
            for _ in 0..*scale {
                let (ra, rf) = self.operand(a);
                self.emit(format!("    MOVF 0x{rf:03X},W,{}", if ra == 0 { "A" } else { "B" }));
                let (fa, ff) = self.operand(0xFE9); // FSR0L
                self.emit(format!("    ADDWF 0x{ff:03X},F,{}", if fa == 0 { "A" } else { "B" }));
                self.emit("    MOVLW 0x00".to_string());
                let (ha, hf) = self.operand(0xFEA); // FSR0H
                self.emit(format!("    ADDWFC 0x{hf:03X},F,{}", if ha == 0 { "A" } else { "B" }));
            }
        }
    }
```

### Task 9: Constant-length `Memcpy`

**Files:**
- Modify: `crates/isel-pic18/src/lib.rs` (`emit_inst`, add `Inst::Memcpy`)

**Interfaces:**

Needed for `structs.c`'s `g = mk(3, 0x1234);`, a whole-struct assignment from a temporary (the sret call's result) into a global, which clang lowers to a `memcpy` of the struct's size. Only `MemLen::Const` is in scope (see this plan's Scope boundary); `MemLen::Reg` panics loudly, matching P2's convention for every not-yet-implemented `Inst` variant.

**A note on why this task orders the two pointers the way it does.** A memcpy has TWO pointers alive (`src`, `dst`), and this plan's whole design (Task 6) uses exactly one indirection register, `FSR0`. If both `src` and `dst` needed `FSR0`-based indirection for the same byte, resolving `dst` second would silently clobber the `FSR0` state `src`'s resolution just set up: a real two-independent-pointers hazard, not a hypothetical one. This task deliberately does NOT solve that in general (a second FSR would be needed, and nothing in this plan's scope has been shown to need it, see the fixture check in Step 3 below); instead it captures the source as a concrete resolved value *before* touching the destination, and explicitly rejects (rather than silently mishandles) the one case that would be unsafe.
