# PIC18 Port P6 (32-bit long + hardware MUL) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PIC18 i32 (`long`) and hardware-multiply support: isel-pic18 emits the 24 injected runtime-routine bodies (`__mul_u8/16/32`, `__udiv_*`, `__sdiv_*`, `__shl_*`...) using PIC18's hardware `MULWF`/`MULLW` (8x8 -> PRODH:PRODL) for the multiplies and PIC18's real branch instructions for the divmod/shift loops, and widens its inline i32 `Bin`/`Icmp`/const-count shift emission to 4 bytes. Acceptance: `long.c` (`in=0x12345678, sin=-19 -> out=0x1634943A`), `muldiv.c` (`in=301 -> out=210`), and P5's deferred `interrupt_mul.c` (ISR-context `__mul_u8`/`__udiv_u8` via the `_isr` duplication) all compile through the real PIC18 pipeline and run correctly in the `Pic18` simulator.

**Architecture:** `legalize` is device-agnostic and already lowers every mul/div/rem/shift (i8/i16/i32) to a typed `Inst::Call` of an injected routine Func (params `a`/`b`, `num`/`den`, `val`/`cnt` + one `__scr` alloca of a fixed size; the exact routine names and `__scr` sizes are the contract, `crates/legalize/src/lib.rs:771-805`). So P6's work is all on the emission side: `isel-pic18` currently (a) panics on i32 `Bin`/`Icmp` and const-count `Bin` shifts ("Task 6+"), and (b) emits a runtime-routine function as an EMPTY label + `RETURN` (its entry block holds only the `__scr` alloca, which `Inst::Alloca` treats as virtual — the silent-fall-through hazard PIC14's `routine_recipe` already guards), so the routine CALLs from legalize currently resolve to nothing. P6 adds: i32 inline arithmetic (the existing `ty.bytes()` loops in `emit_inst` already generalize to 4 bytes; only the asserts and the i16-specific icmp/shift paths gate them), const-count shift inlining (PIC18 `RLCF`/`RRCF` through carry), and `emit_routine` bodies for all 24 routine names.

**The key simplification:** PIC18 has REAL branch instructions (`BNC`, `BZ`, `BRA`, ...), unlike PIC14's skip-sensitive `BTFSS`/`INCFSZ` idioms. The PIC14 recipes' single-GPR-bank constraint (`assert_bank0`, `alloc`'s routine-base rounding) exists BECAUSE a `BANKSEL` inserted between a skip-test and its target would change the skip; PIC18's branches are absolute targets that a `MOVLB` never disturbs. The PIC18 recipes therefore need NO bank constraint, NO `assert_bank0`, and `alloc`'s `routine_base` rounding is inert (the single contiguous PIC18 region never straddles — verified, `alloc/src/lib.rs:176-191` handles a one-region device trivially). **The muls use hardware `MULWF`** (the headline of docs/29 §1's "No multiply instruction" row): `MULWF f` computes `W * f -> PRODH:PRODL` (sim: `crates/sim/src/lib.rs:677-683`), so the shift-and-add loops PIC14 needs vanish. u8 mul = one MULWF; u16 mul = 4 schoolbook partials; u32 mul = 16 partials summed low-32-bits.

**Tech Stack:** Rust, Cargo workspace, docker dev image (rustc 1.97.1, clang 20.1.8, gpasm 1.5.2). `Pic18` simulator + `gpasm -p p18f4550` are the oracles.

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md) §4 P6 row ("32-bit `long`, and hardware `MUL` throughout"), §1's mul row (`MULWF` single-cycle 8x8). PIC14 reference: [`docs/21-integer-spine-m8-runtime-muldiv-plan.md`](../../21-integer-spine-m8-runtime-muldiv-plan.md) and `crates/isel/src/lib.rs`'s `emit_routine` recipes (the algorithms to port). The injected routine `Func` shape and `__scr` sizes are the cross-crate contract in `crates/legalize/src/lib.rs` (the `# The scratch layout contract` table, `__scr` sizes: `__mul_u8` 6, `__mul_u16` 14, `__mul_u32` 11, `__udiv_u8`/`__urem_u8` 4, `__udiv_u16`/`__urem_u16` 7, `__sdiv_i8`/`__srem_i8` 5, `__sdiv_i16`/`__srem_i16` 7, `__udiv_u32`/`__urem_u32` 10, `__sdiv_i32`/`__srem_i32` 12, shifts 3/4/2).

## Ruling: PIC18 recipes are branch-based, not skip-based (no single-bank constraint)

The PIC14 recipes are skip-sensitive (`BTFSS f,0 / GOTO skip`, the `INCFSZ f,W` carry fold). Porting them verbatim with PIC18 mnemonics (BTFSS + BRA) is possible but pointless: PIC18 has `BZ`/`BNZ`/`BNC`/`BC`/`BOV`/`BN` real branches AND the same `BTFSC`/`BTFSS` skip forms. The recipe bodies use either:
- **`BTFSS f,bit` + `BRA target`** — NOT skip-sensitive across the branch (the BRA is the target, never skipped), so a `MOVLB` between them is harmless. PIC18's `BNC`/`BZ` etc. make the carry/fold idioms one branch, not two.
- **Hardware mul**: `MULWF`/`MULLW` compute into PRODH:PRODL with no loop.

Consequence: **the routine recipes have NO single-GPR-bank constraint on PIC18**. `alloc`'s `routine_base` rounding already no-ops for the single PIC18 region; `isel-pic18` adds NO bank assert. This is a deliberate simplification (like P3's "no FSR-window checks"), not an oversight.

**Cost if wrong:** a recipe with a misplaced branch targets the wrong offset. Every recipe gets a sim test with hand-computed inputs, exactly like PIC14's.

## Global Constraints

- **`isel` (PIC14) never regresses.** No changes to `crates/isel`, `crates/legalize`, `crates/alloc`, `crates/ir`, `crates/irparse` in this plan. The PIC14 mul/div fixtures keep passing unchanged.
- **The routine name + `__scratch` size contract is legalize's.** `routine_name` (op, ty) is already device-agnostic; P6 does not touch it. `isel-pic18` emits a body for every `ir::is_runtime_routine` name that reaches it; an unknown one panics (same as PIC14's `routine_recipe` panic).
- **Results land in the fixed retval region** (`0x0000-0x0003`, `Gen.retval_lo`), which `Inst::Call`'s return-copy already reads (`for i in 0..ty.bytes() { emit_copy_byte(retval_lo + i, dst + i) }`). The recipes write the result there and `RETURN`; no other store.
- **`__scr` sizes must fit the injected alloca** but the internal offsets are PIC18's own: the PIC18 recipes choose their own scratch layout within the legalize-specified size. (The size is the contract; the offset table is PIC14-specific and not bound.)
- **Hardware mul for ALL widths**: `MULWF`/`MULLW` are the primitives; no shift-and-add mul loop anywhere on PIC18. u8: 1 MULWF. u16: 4 partials. u32: 16 partials (low 32 bits).
- **Interrupt context**: `split_isr_routines` (P5's legalize machinery) injects `__mul_u8_isr` etc. with their own frames; the recipe dispatch strips `_isr` to the base recipe but keeps the copy's own slots (PIC14's `routine_recipe` pattern). The `_isr` copy runs the same body against ITS slots — the recipe code must read slots from `cur_func`'s map, never hard-code.
- Conventional commits, single line, ≤ 3 lines.
- No external assembler; gpasm is test-oracle only.

### Task 3: runtime-routine recipe bodies (the big one)

**Files:**
- Modify: `crates/isel-pic18/src/lib.rs` — `select`'s per-function loop (a routine emits its recipe, not the generic label+RETURN), new `emit_routine`.
- Modify: `crates/isel-pic18/tests/isel_pic18.rs`

**Interfaces:**
- Consumes: `ir::is_runtime_routine(name)` (the name set), the injected `Func` shapes (`param a/b`, `num/den`, `val/cnt`, `__scr` alloca of the legalize-fixed size).
- Produces: for each routine name, a PIC18 body:
  - **`__mul_u8`** (scr size 6): `MOVLW 0; MULWF b -> PRODH:PRODL`? No — MULW wants a in W: `MOVF a,W; MULWF b; store PRODL -> retval`. 3 instructions. (`PRODL` = 0xFF3, `PRODH` = 0xFF4.)
  - **`__mul_u16`** (size 14): schoolbook: 4 `MULWF` partials (a0×b0, a0×b1, a1×b0, a1×b1), accumulate low 4 bytes with carries. Layout: `p0_lo..p3_hi` in scratch, or accumulate in a 4-byte `r` (scr offsets). Output the low 2 bytes.
  - **`__mul_u32`** (size 11): 16 `MULWF` partials, low 32 bits; the PIC18 `MULWF` muls are 8-bit, so this is 16 partial products summed mod 2^32 (drop the high bytes).
  - **`__udiv_u8`/`__urem_u8`** (size 4): 8-iteration restoring division; PIC18 branches (`BNC` = no borrow → restore).
  - **`__udiv_u16`/`__urem_u16`** (size 7): 16-iteration.
  - **`__udiv_u32`/`__urem_u32`** (size 10): 32-iteration.
  - **`__sdiv_i*`/`__srem_i*`**: sign flags (bit0 neg q, bit1 neg r), abs in place, unsigned divmod, negate per flags — the PIC14 structure ported.
  - **`__shl_*`/`__lshr_*`/`__ashr_i*`** (sizes 3/4/2): masked count, `DECFSZ` loop with `RLCF`/`RRCF` per byte (the PIC14 `emit_shift_body` port, but the count lives in `__scr`).
- **`_isr` variants**: the recipe body is emitted under the copy's own name (`__mul_u8_isr` etc.), reading `a`/`b`/`__scr` from THAT function's map — `routine_recipe`-style base-name dispatch. A copy's body is the SAME recipe with ITS slots.

- [ ] **Step 1: Write the failing tests** — one test per routine family asserting the emitted body exists (substring) and the sim runs it: `__mul_u8(7, 5) = 35`, `__mul_u16(0x1234, 0x5678) = ...`, `__udiv_u8(59, 3) = 19`, `__sdiv_i8(-19, -3) = 6`, `__ashr_i8(0x80, 3) = 0xF0`, etc. Use the existing `sim_run_bytes` pattern (emitted asm + PIC18 sim via `assemble_file_to_hex`).
- [ ] **Step 2: Run to verify they fail** — the routine label currently emits as an empty body + `RETURN` (or the `select` loop's `Inst::Alloca` no-op leaves nothing), so the CALL target resolves to a fall-through — the sim returns garbage or never halts.
- [ ] **Step 3: Implement `emit_routine`** — dispatch by name; the recipes per the above + the PIC14 body ported with PIC18 mnemonics; a branch-based not skip-based loops. The sim's `exec_cond_branch` (`BNC` etc.) and `RLCF`/`RRCF` (0x3400/0x3000 arms) already exist (scout verified), so no sim change.
- [ ] **Step 4: Run to verify they pass** — all routine sim tests green, workspace green.
- [ ] **Step 5: Commit** — `feat(isel-pic18): runtime routine bodies (hw mul, divmod, shifts)`.
