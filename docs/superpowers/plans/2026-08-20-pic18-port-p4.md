# PIC18 Port P4 (const via TBLRD) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `isel-pic18` gains `const` (flash) support via PIC18 `TBLRD` ( `TBLPTR`/`TABLAT` ), bringing PIC18 codegen to parity with PIC14's milestones 7/10 for `const`. `const` globals have no RAM address (`alloc` already does this; `const_globals` set); every `load` through a pointer that resolves to a `const` global is lowered to a `TBLPTR`-setup + `TBLRD*` + `TABLAT` copy instead of `FSR`/`INDF` or `RETLW`. Acceptance: `const_table.c` (300-byte table, chunk boundary reads) and the full `ptr_probe.c` (RAM pointer feeding a `const` read) compile through the real driver pipeline and run correctly in the `Pic18` simulator. The 511-byte ceiling (PIC14's two-chunk `RETLW` limit) stops existing: tables up to the simulator's flash size (0x4000 words = 32768 byte addresses) are linear.

**Architecture:** PIC14's `const` model ( `RETLW` jump tables, 256-byte `PCLATH` windows, chunk chaining, `PAGE`/`LOW` dance ) is deleted for PIC18. PIC18 has no window: `TBLPTR` is a 21-bit byte address (`TBLPTRU:TBLPTRH:TBLPTRL` = SFRs `0xFF8:0xFF7:0xFF6`) and `TABLAT` (`0xFF5`) holds the read byte; `TBLRD*` / `TBLRD*+` / `TBLRD*-` / `TBLRD+*` are single-word opcodes (`0x0008`–`0x000B`). The flash model is byte-packed (two bytes per 16-bit word, little-endian: even byte = word low, odd byte = word high), matching `gpasm -p p18f4550`'s `DB` packing. `alloc` is untouched (it already excludes `const` globals from RAM; `crates/alloc/src/lib.rs:241` `const_globals` set). The new work is in three crates: `asm` (encode the four `TBLRD*` opcodes, pack `DB` bytes, accept `UPPER()`), `sim` (`Pic18` executes `TBLRD*` via `TBLPTR`→`prog`→`TABLAT`), and `isel-pic18` (detect `Base::Global(const)` or `Gep` into const, emit `TBLPTR` setup + `TBLRD*` per loaded byte, emit the tables themselves as `DB` after `__start`).

**Tech Stack:** Rust, Cargo workspace, `docker` dev image (rustc 1.97.1, `gpasm` 1.5.2). `Pic18` simulator and `gpasm -p p18f4550` remain the oracles.

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md) §1 table (`const` row: `RETLW` → `TBLRD`), §2 D-1 (parallel backend: only `isel-pic18` changes), §4 P4 row. PIC14 reference: [`docs/18-phase3-pointers-const-plan.md`](../../18-phase3-pointers-const-plan.md) and `crates/isel/src/lib.rs` `global_is_const` / `emit_ptr_load_byte` RETLW path (the shape being replaced). Datasheets to `[VERIFY]` before hard-coding: `TBLPTRU/H/L` SFR byte addresses (`0xFF8/0xFF7/0xFF6`), `TABLAT` (`0xFF5`), `TBLRD*` opcodes (`0x0008`–`0x000B`), and `PC` byte-oriented vs word-oriented semantics already proven in P1 ( `asm` stores PIC18 symbols as byte addresses; `sim` indexes `prog` as `(pc/2)` ).

## Scope boundary

**In scope:** `const` globals (`is_const` true) of any size that fits flash (no 255/511 caps); scalar `i8`/`i16` const reads (including `gep` chain + dynamic `terms` with one term, matching P3's `terms.len()<=1` bound); `i32`/`float` const tables where the `load`'s `Ty` implies multiple `TBLRD` bytes per logical value (existing `Ty::bytes()` loop); `memcpy` with a `const` source is **out** and panics (loads cover the fixtures).

**Out of scope (panics loudly):** `store` through a `const` base (ROM is not writable); `memcpy` with an indirect-const source; multi-term dynamic indices (`terms.len()>1`); self-modifying flash writes (`TBLWT`).

**The 511-byte ceiling is deleted:** no chunk dispatch. A 300-byte table is a single `DB` blob; a 600-byte table would be two adjacent label ranges but still one linear `TBLPTR` addition. The fixtures that test 3-chunk (>512) behaviour on PIC14 become a linear test on PIC18 (≈600 bytes still fits).

## Global Constraints

- **`isel` (PIC14) never regresses.** No change to `crates/isel/src/lib.rs` RETLW/chunk reader; PIC14 keeps its 511-byte limit and its fixtures.
- **`alloc`, `device`, `legalize`, `wholeprog` are untouched.** `alloc` already handles `const` exclusion; `device::PIC18F4550.flash_words = 0x4000` stays.
- **One `TBLPTR` model, no hidden state.** Every const-byte load recomputes `TBLPTR = table_base + k + Σ scale×%reg + byte_off` from scratch (per-byte re-setup, mirroring P3's per-byte `FSR0` re-setup). No `TBLRD*+` auto-increment optimisation; that would tie multi-byte loads to ordering.
- **No `PCLATH`/`PAGE` machinery.** `LOW`/`HIGH`/`UPPER` helpers resolve through the PIC18 byte-address symbol table. `UPPER()` is ` (addr>>16) & 0xFF` (zero for `0x4000`-word devices but correct for the encoding).
- **Byte-packed flash.** `DB 0xXX` packs two per word little-endian. `asm` and `sim` agree on this packing and on even/odd `TBLPTR` selection. `gpasm` cross-checks must use the same `DB` packing the simulator does.
