# PIC18 Port P2 (Integer Spine Codegen) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real IR-to-PIC18-assembly codegen for the "integer spine" — the same C surface the original PIC14 backend's milestones 2-6 covered (scalar `i8`/`i16` arithmetic, all ten `icmp` predicates, casts, `select`, non-recursive calls with overlay allocation, control flow) — through a new `isel-pic18` crate, verified end to end against the same four fixtures the PIC14 backend used: `add.c`, `scalar.c`, `overlay.c`, `banked.c`.

**Architecture:** `isel-pic18` is a new, separate crate (per the already-approved D-1 decision: PIC14's `isel` stays untouched, PIC18 gets its own backend, not a shared generic one) with the exact same `select(device, m, addrs) -> String` shape as `isel::select`. Two things turn out to need genuinely new design and two turn out to need almost none:
- **`alloc` needs zero PIC18-specific code.** Its overlay algorithm and `region_for`/`place_at` bank-stepping already read entirely off `Device::ram_banks`/`common_ram` (introduced in P0). PIC18's GPR space (`0x000-0x7FF`, minus a small reserved retval region) is one contiguous range with no scattered SFR holes the way PIC14's four banks have — so the `PIC18F4550` profile just needs `ram_banks: &[(gpr_start, 0x7FF)]`, a single entry, and the existing generic code handles the rest correctly.
- **PIC18 needs no `banking` crate counterpart at all.** Every PIC18 instruction already encodes its own access/bank bit (`a`) directly (P1's encoder always emits it explicitly), so there's nothing to *infer* from already-emitted text the way PIC14's post-pass does. `isel-pic18` tracks the current `BSR` value inline during codegen and emits `MOVLB` itself, exactly where PIC14's *encoder* — not a separate pass — already handles the `a` bit per instruction.
- **`Slot` (from P0) needs to move into a new tiny `iselcore` crate** so both `isel` and `isel-pic18` share it, rather than duplicating it — this is the trigger point docs/29's crate layout table anticipated for `iselcore`.
- **`isel-pic18` needs real new lowering logic**, but PIC18's richer instruction set makes much of it *simpler* than PIC14's: `MOVFF` (a full 12-bit-addressed memory-to-memory move, no access/bank bit at all) makes every plain copy — `Load`, `Store`, `Phi` copies, `Call` argument/retval copies — a direct one-or-two-instruction sequence with **zero banking complexity**. Only instructions that route a value through `W` (arithmetic, comparisons) need the access-bit/`BSR` tracking machinery at all.

**Tech Stack:** Rust, Cargo workspace, `nix develop` dev shell. `gpasm -p p18f4550` (byte-for-byte) and the `Pic18` simulator (both already built and verified in P1) are the acceptance oracles for the four e2e fixtures; individual instruction-lowering unit tests assert on emitted-assembly substrings, mirroring `isel`'s own existing test convention exactly (`crates/isel/tests/isel.rs`).

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md) — §4's P2 row ("Integer spine: `isel-pic18`, Access Bank + BSR banking, `Slot::Direct`." / fixtures: `add.c`, `scalar.c`, `overlay.c`, `banked.c`), §2 D-1 (parallel backend crates), §2 D-2 (`Slot`), §3 (crate layout: `iselcore`, `isel-pic18`).

## Scope boundary (matches the current `isel` crate's own milestone-2-6 boundary exactly)

**In scope** — the `Inst` variants: `Load`, `Store`, `Bin` (add/sub/and/or/xor only — `mul`/`udiv`/`urem`/`sdiv`/`srem` and variable-count shifts are routed to runtime-routine `Call`s by `legalize` before `isel-pic18` ever sees them, and none of P2's four fixtures use them, so the routine *bodies* — which would need their own PIC18 assembly — are not needed yet), `Icmp` (all ten predicates), `Zext`/`Sext`/`Trunc`, `Select`, `Call`/`Ret` (scalar args + `byval`/`sret`, non-recursive), `Br`/`BrCond`, `Phi`.

**Out of scope** (unchanged from PIC14's own milestone boundary, matching later PIC18 phases): `Gep`/`Alloca`/`Memcpy`/pointers (P3), `const` flash tables (P4), interrupts (P5), 32-bit `long` and runtime-routine bodies (P6), soft-float (P7). If a fixture accidentally needs one of these, that's a sign the fixture (or this plan) is wrong, not a reason to implement it now.

## Where the `retval`/`scratch` design comes from

PIC14's `isel` reserves a few bytes of its device's bank-independent `common_ram` for two things: a `scratch` byte (used by pointer-address arithmetic and multi-byte equality accumulation — both **out of scope for P2**, since P2 has no pointers) and a 4-byte `retval_lo` region (`Inst::Ret` writes a function's return value there before `RETURN`; `Call`'s `emit_call` reads it back into the call's `dst` slot right after `CALL` returns — see `crates/isel/src/lib.rs:1868-1876` and `:1483-1492`). **P2 only needs the `retval` region** (no scratch byte — see Task 7 and Task 9's notes on why PIC18's instruction set avoids needing one). Reserving it in PIC18's low access-bank range (`0x00-0x03`, reachable via `a=0` with no `BSR` dependency) mirrors PIC14's exact rationale: a `Ret` and the `Call` that reads it back can run with the tracked `BSR` in different states, so a `BSR`-independent fixed location avoids an extra `MOVLB` around every return.

## Global Constraints

- **`isel` (PIC14) must never regress.** This plan only edits it in Task 2 (extracting `Slot` into `iselcore`), which must be a pure, behavior-preserving refactor — `cargo test -p isel` must show the exact same test count and assertions before and after.
- **`alloc`/`banking`/`legalize`/`callgraph`/`ir`/`irparse`/`wholeprog` are not touched**, except `alloc`'s own tests are unaffected since its code doesn't change at all — only the `device` crate's `PIC18F4550` constant changes (Task 1).
- **No PCLATH-equivalent paging exists on PIC18** (20-bit `GOTO`/`CALL` reach the whole 32KB flash in one shot) — `isel-pic18` never emits anything like PIC14's `PAGE()`/`emit_pclath_restore` machinery, and `driver` skips `isel::verify_page_fit` entirely for a `Core::Pic18` device (Task 14).
- **No BANKSEL-reclaim optimization pass (PIC14 issue #13's equivalent) in P2.** `isel-pic18` resets its tracked `BSR` to "unknown" at every block label (conservatively re-emitting `MOVLB` on the next banked access), matching PIC14's *pre*-issue-#13 baseline. This is correct, just not optimal; revisit only if a later issue asks for it, exactly like PIC14's own history.
- Conventional commits, single line, at most 3 lines. Branch: `feat/pic18-p2-integer-spine` (already created, forked from master with P0/P1 merged).

```rust
//! `isel-pic18` — instruction selection for the PIC18 integer spine (P2).
//! Same scope as `isel`'s milestones 2-6 (`Load`/`Store`/`Bin`(add/sub/
//! and/or/xor)/`Icmp`/`Zext`/`Sext`/`Trunc`/`Select`/`Call`/`Br`/`BrCond`/
//! `Phi`/`Ret`) — see docs/superpowers/plans/2026-08-18-pic18-port-p2.md.
//! A separate crate from `isel` per docs/29-pic18-port-design.md §2 D-1:
//! the instruction sets differ enough that sharing would leak an
//! abstraction, and PIC14's working code must never be at risk from a
//! PIC18 edit.

use std::collections::HashMap;

use device::Device;
use ir::{Inst, Module, Ty, Val};
use iselcore::{ssa_key, Slot};

struct Gen<'m> {
    m: &'m Module,
    addrs: &'m HashMap<String, u16>,
    /// Fixed, `BSR`-independent return-value region (up to 4 bytes, from
    /// `device.common_ram`) — see the plan's "Where the retval/scratch
    /// design comes from" section.
    retval_lo: u16,
    /// The `BSR` value the last-emitted `MOVLB` set, or `None` when it's
    /// unknown (module start, or just after a label — branch targets can
    /// be reached with any prior `BSR` state, so it must be re-established
    /// on the next banked access rather than assumed).
    bsr: Option<u8>,
    cur_func: &'m str,
    /// Module-scoped fresh-label counter (mirrors `isel`'s `tmp` field).
    tmp: u32,
    out: Vec<String>,
}

impl<'m> Gen<'m> {
    fn emit(&mut self, s: impl Into<String>) {
        self.out.push(s.into());
    }

    fn fresh_label(&mut self) -> String {
        let s = format!("tmp{}", self.tmp);
        self.tmp += 1;
        s
    }

    fn slot_addr(&self, func: &str, name: &str) -> Slot {
        Slot::Direct(
            *self
                .addrs
                .get(&ssa_key(func, name))
                .unwrap_or_else(|| panic!("isel-pic18: no slot for {func}::{name}")),
        )
    }
    fn val_addr(&self, v: &Val) -> Slot {
        match v {
            Val::Reg(r) => self.slot_addr(self.cur_func, r),
            Val::Global(g) => Slot::Direct(
                *self
                    .addrs
                    .get(g)
                    .unwrap_or_else(|| panic!("isel-pic18: no address for @{g}")),
            ),
            Val::Const(k) => Slot::Direct((*k & 0xFF) as u16),
        }
    }
    fn global_addr(&self, name: &str) -> u16 {
        *self
            .addrs
            .get(name)
            .unwrap_or_else(|| panic!("isel-pic18: no address for @{name}"))
    }

    /// The `,A`/`,B` operand components `(a, f)` for a physical address
    /// used by a `W`-routing instruction (`ADDWF`/`SUBWF`/.../`CPFSxx`),
    /// emitting `MOVLB` first if the tracked `BSR` doesn't already match.
    /// `MOVFF`-based plain copies (`emit_copy_byte`, below) never call
    /// this — they take full 12-bit addresses directly and need no bank
    /// bit at all, which is why `Load`/`Store`/`Phi`-copies/`Call`-arg-
    /// copies (Tasks 4, 11, 12, 13) never touch `BSR`.
    fn operand(&mut self, addr: u16) -> (u16, u16) {
        if addr < 0x60 {
            (0, addr & 0xFF)
        } else {
            let bank = (addr >> 8) as u8;
            if self.bsr != Some(bank) {
                self.emit(format!("    MOVLB 0x{bank:X}"));
                self.bsr = Some(bank);
            }
            (1, addr & 0xFF)
        }
    }

    /// One byte, memory-to-memory, via `MOVFF` — no access bit, no `BSR`.
    fn emit_copy_byte(&mut self, src: u16, dst: u16) {
        self.emit(format!("    MOVFF 0x{src:03X}, 0x{dst:03X}"));
    }

    fn emit_inst(&mut self, i: &Inst) {
        match i {
            Inst::Ret(None) => self.emit("    RETURN".to_string()),
            other => panic!("isel-pic18: unsupported instruction for P2 (so far): {other:?}"),
        }
    }
}

pub fn select(device: &Device, m: &Module, addrs: &HashMap<String, u16>) -> String {
    let (common_lo, _) = device
        .common_ram
        .expect("isel-pic18's fixed retval region needs a common-RAM reservation");
    let mut out = vec![
        "; pic8 -- P2 integer spine (isel-pic18)".to_string(),
        format!("    list p={}", device.name),
        "    radix hex".to_string(),
        "".to_string(),
        "    org 0x0000".to_string(),
        "    goto __start".to_string(),
        "".to_string(),
    ];
    for f in &m.funcs {
        let mut g = Gen {
            m,
            addrs,
            retval_lo: common_lo,
            bsr: None,
            cur_func: &f.name,
            tmp: 0,
            out: Vec::new(),
        };
        for b in &f.blocks {
            for inst in &b.insts {
                g.emit_inst(inst);
            }
        }
        out.extend(g.out);
    }
    // `__start` calls `main` and halts; matches the shape `isel::select`
    // uses for its own program entry, minus the ISR machinery (P5).
    out.push("__start:".to_string());
    out.push("    call main".to_string());
    out.push("    sleep".to_string());
    out.join("\n") + "\n"
}
```

    /// register/global source uses `MOVFF` (no access bit needed); a
    /// constant has no `MOVFF` literal form, so it goes through `W` via

    fn emit_move_val_to_slot(&mut self, val: &Val, ty: Ty, dst: u16) {

                    g.emit_load_w(&bc.cond, 0);
                    g.emit(format!("    BZ {}", labels[&bc.f]));
                    g.emit(format!("    BRA {}", labels[&bc.t]));

                Some(Inst::Ret(None)) => g.emit("    RETURN".to_string()),

                        g.emit(format!("    MOVWF 0x{f2:03X},{bank}"));

                    g.emit("    RETURN".to_string());
                }
                _ => panic!("isel-pic18: block has no terminator"),
            }
