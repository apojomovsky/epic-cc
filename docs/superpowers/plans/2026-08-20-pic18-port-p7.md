# PIC18 Port P7 (Soft-float) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PIC18 soft-float support: `isel-pic18` emits the nine IEEE754 f32 runtime routine bodies (`__add_f32`, `__sub_f32`, `__mul_f32`, `__div_f32`, `__cmp_f32`, `__uitofp_f32`, `__sitofp_f32`, `__fptoui_f32`, `__fptosi_f32`) that legalize already injects and lowers to calls for, ported from PIC14's machine-verified recipes. Acceptance: `float.c` (in=3.0f) compiles through the real PIC18 pipeline and runs correctly in the `Pic18` simulator with the bit-exact expected values: `out1=0x3F99999A`, `out2=0x41100000`, `out3=0x3EAAAAAB`, plus `s.c`/`s.f` via the struct byval/sret path.

**Architecture:** Everything target-independent already exists and is shared: legalize lowers every `FloatBin`/`Fcmp`/`FloatConv` to typed `Inst::Call`s of the nine injected routines (the fcmp tri-state byte 0=eq/1=lt/2=gt/3=nan materialized as an icmp/select tree over `%c = call i8 @__cmp_f32`), and isel-pic18's `Inst::Call` arm already copies 4-byte args + 4-byte retvals. P7's work is purely the recipe bodies: port PIC14's `emit_routine` float arms (`crates/isel/src/lib.rs:2741-4839`) to PIC18 mnemonics. The port is mechanical — every instruction maps 1:1 (RLF→RLCF, RRF→RRCF, BTFSS/BTFSC/GOTO skip pairs preserved, `INCFSZ`/`DECFSZ`/`ADDWFC`/`SUBFWB`/`MOVLW`/`ADDLW` etc. all exist on PIC18, and the simulator's `skip_pc` handles the two-word skipped-GOTO case exactly).

**The one load-bearing port rule: the float recipes are SKIP-SENSITIVE, so their frames must live in the access-bank GPR region.** The recipes' carry idioms (`BTFSC STATUS,0; INCFSZ f,W; ADDWF g,F`) and bit-test skips (`BTFSS f,7; GOTO label`) break if a `MOVLB` is inserted between the test and its target (the banking pass's BANKSEL hazard PIC14 solved with `assert_bank0`). On PIC18, isel-pic18's own `operand()` emits `MOVLB` for banked-GPR addresses (0x060-0xF5F); addresses ≤ 0x5F (the low access-bank GPR) get `a=0` and NO `MOVLB`. So: **every float routine's slots (params + `__scr` + retval) must sit at addresses ≤ 0x5F, and `isel-pic18` asserts this at emission** (the PIC18 analog of PIC14's `assert_bank0`, same reasoning). The `float.c` fixture's frames fit (PIC18's access GPR starts at 0x0000 with the P5 reservations, globals at 0x0010, ~0x20 for four floats, routine frames ending ~0x59 — all ≤ 0x5F); if the empirical layout overflows, the implementer adjusts the fixture (fewer defs) rather than weakening the assert.

**Tech Stack:** Rust, Cargo workspace, docker dev image (rustc 1.97.1, clang 20.1.8, gpasm 1.5.2). `Pic18` simulator + `gpasm -p p18f4550` are the oracles.

**Spec:** [`docs/29-pic18-port-design.md`](../../29-pic18-port-design.md) §4 P7 row, §2 D-1's "the nine soft-float routines will be written twice. This is accepted" consequence. The reference is [`docs/28-phase7-softfloat-plan.md`](../../28-phase7-softfloat-plan.md) (the algorithm design) and `crates/isel/src/lib.rs`'s float recipe code (`emit_f32_*`), which the P7 body ports. The routine `Func` shapes and `__scr` sizes are legalize's contract (`crates/legalize/src/lib.rs:756-760`): `__add_f32`/`__sub_f32`/`__mul_f32` scr 14, `__div_f32` scr 12, `__cmp_f32` scr 6, `__uitofp_f32`/`__sitofp_f32` scr 8, `__fptoui_f32`/`__fptosi_f32` scr 8; params `a`/`b` (f32, 4 bytes) or `val` (4 bytes).

## The substitution table (the mechanical core of every task)

Port each recipe line by line from `crates/isel/src/lib.rs`, with these substitutions:

| PIC14 | PIC18 | Notes |
|---|---|---|
| `RLF f` / `RRF f` | `RLCF f,F,A` / `RRCF f,F,A` | rotate-through-C, identical semantics |
| `BTFSC STATUS,0` | `BTFSC 0xFD8,0,A` | STATUS C = SFR 0xFD8 bit 0 |
| `BTFSS STATUS,0` | `BTFSS 0xFD8,0,A` | |
| `BTFSC STATUS,2` | `BTFSC 0xFD8,2,A` | STATUS Z = bit 2 |
| `BTFSS STATUS,2` | `BTFSS 0xFD8,2,A` | |
| `BTFSS f,bit` + `GOTO label` | same mnemonics | PIC18 skips 2 words when the skipped instr is a 2-word form (GOTO); sim's `skip_pc` handles it |
| `MOVF f,W` / `MOVWF f` / `ADDWF f,F` / ... (byte/bit ops) | `MOVF 0x{f:03X},W,{A\|B}` etc. | route through the ported `operand()` (task-wide: adds the `,A`/`,B` and MOVLB where needed; the ≤ 0x5F assert keeps every recipe slot in `A`) |
| `MOVLW 0x00` / `ADDLW 0x01` / `SUBLW` | same | literal ops identical |
| `MOVWF PCLATH` | (none in float recipes) | |
| retval writes | `store_retval`-style: `MOVFF 0x{r:03X}, 0x{retval_lo+i:03X}` | isel-pic18 already has `store_retval`; the float bodies call it |
| `INCFSZ f,W` carry fold | same | leaves C untouched on skip (sim 0x3C00), identical |

**The `operand` helper** (isel-pic18, already exists) returns `(a, f)` with the `,A`/`,B` suffix and emits `MOVLB` for banked GPR only; the float emitters must go through it for every byte/bit instruction (like the P2-P6 emitters already do).

**Sanity assertions to add in `emit_routine` float arms:** `assert!(slot <= 0x05F, "float routine {name} frame exceeds the access-bank GPR region (0x{slot:03X} > 0x05F)")` for every param/`__scr`/retval byte — the skip-sensitivity rule above. (PIC14's `assert_bank0` analog.)

## Global Constraints

- **`isel` (PIC14) never regresses.** No changes to `crates/isel`, `crates/legalize`, `crates/alloc`, `crates/ir`, `crates/irparse`, `crates/device`, `crates/asm/src` in this plan. PIC14's float suite keeps passing unchanged.
- **The recipes are ported, not re-derived.** The algorithms (IEEE754 decode/encode, implicit bit, RNE guard/sticky/LSB, denormal handling, div's 24+25 restoring iterations, the fcmp tri-state) are machine-verified; changing them is out of scope. The port is instruction-substitution + the frame assert.
- **`_isr` variants are handled by the existing dispatch** (P6's `emit_routine` strips `_isr` to the base recipe; legalize already injects the float `_isr` copies for interrupt contexts).
- Conventional commits, single line, ≤ 3 lines.
- No external assembler; gpasm is test-oracle only.
